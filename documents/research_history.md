# これまでの試行錯誤の整理

整理日：2026-11-10。対象は、このリポジトリのコード・文書・Git履歴から確認できる取り組み。
会話や手元だけに残っている検討は未収録。手法の採用理由が記録されていない部分は、実装から読み取れる狙いとして記述する。

## 1. 研究の中心にある問い

**閉路を持つ有向グラフを、辺の向きを保ったまま、トーラス上の階層描画として見やすく配置できるか。**

そのために、主に次の自由度を分けて扱ってきた。

| 工程 | 決めること | 改善したいもの |
| --- | --- | --- |
| 階層数の決定 | 周期となる階層数 | 境界通過辺数との両立、不要に多い階層の抑制 |
| 階層割当 | 各頂点が属する階層 | 周期スパン、長辺、ダミー増加 |
| 交差削減 | 各層の循環順序と辺の巻き数 | 辺同士の交差 |
| 回転・切れ目選択 | 循環順序のどこを表示境界にするか等 | 回り込みや境界通過線分 |
| 座標割当 | 順序を具体的な位置にする | 辺の変位、曲がり、頂点間隔 |
| 全体評価 | 各工程の組み合わせ | 完成描画の品質と計算時間 |

現行パイプラインは次の構成になっている。

```text
グラフ生成
  → 境界通過辺数と階層数の探索
  → スパンを整える階層割当
  → 長辺へのダミー挿入
  → 円形重心による初期順序
  → global guard付きradial sifting
  → 回転調整（交差が増えたら戻す）
  → 切れ目選択DP
  → 座標割当
  → 描画・評価
```

既定値は階層割当 `diff_square`、sifting 5回、切れ目選択あり、座標割当 `brandes_koepf`。
根拠：[設定](../src/torus_layout/models.py)、[パイプライン](../src/torus_layout/pipeline.py)、[利用方法](../src/torus_layout/README.md)。

## 2. 階層数・階層割当で試したこと

### 2.1 複数の目的を一括で最適化する方式

| 試した方式 | 狙い・仕組み | 現在の位置づけ・注意点 |
| --- | --- | --- |
| 初期モデル `torus` | 階層数・辺スパン・トーラス辺数を重み付き目的で扱う | 初期の定式化。[実装](../src/old_torus_layout/layer_assignment/torus.py) |
| `torus_iqp` | スパンの二乗を直接目的関数に入れ、長辺を強く罰する | 旧系統に残る比較候補。係数の一部は関数内で再設定される。[実装](../src/old_torus_layout/layer_assignment/torus_iqp.py) |
| `torus_ilp` | スパンの値をone-hot変数で選び、二乗費用を線形化する | 同じ二乗費用でも定式化を変える試み。現在の二段階方式とは制約・周期の扱いが異なる。[実装](../src/old_torus_layout/layer_assignment/torus_ilp.py) |
| SCCを用いたヒューリスティック | SCC分解、縮約DAGの階層化、SCC内部の周期的な順位改善 | 求解負担を抑えるための別系統。現行パイプラインには統合されていない。[実装](../src/old_torus_layout/layer_assignment/torus_heuristic.py) |

この系統では、複数の目的の優先度を重みで調整している。現行方式では、境界通過辺数・階層数の決定とスパンの最適化を分離している。
この変化を「一括モデルが性能面で劣ったため」とまでは、現存資料だけから断定しない。

旧モデルでは距離式に `M=n` を使う箇所がある一方、現行モデルは選んだ階層数 `L` を周期とする。
旧モデルと現行モデルの目的値は、そのまま同じ尺度として比較しない。

### 2.2 階層数をどう決めるか

| 試した考え方 | 参照先 | 現在の位置づけ |
| --- | --- | --- |
| グラフ直径、最長閉路、ランダムDFSによる閉路推定 | [階層数推定群](../src/old_torus_layout/layer_length/) | グラフの特徴から階層数を与える旧系統 |
| FASに基づく推定、SCC縮約DAGの最長路、最大SCCサイズ | [階層数推定群](../src/old_torus_layout/layer_length/) | 他の構造指標も試した記録 |
| 固定階層数で境界通過辺数を最小化 | [旧実装](../src/old_torus_layout/layer_assignment/torus_minimize_torus_edge.py)、[現行実装](../src/torus_layout/layering/minimize_wraps.py) | 二段階方式の基礎 |
| 二分探索 | [探索](../src/torus_layout/layering/search.py) | 大きな階層数で得た最小境界通過辺数を達成する、最小の階層数を探す |

**現行ステップ1の優先順位は「境界通過辺数、次に階層数」。単に階層数だけを最小化しているわけではない。**

最適性を証明した求解を前提に、階層数を増やしても最小境界通過辺数が増えないことと、上限 `nΛ` の十分性を整理済み。
ただし現行コードのTIME_LIMIT等の扱いまで含めて、常に辞書式最適性が保証されるわけではない。
詳細：[二分探索の正当性](layer_count_search_correctness.md)。

### 2.3 二段階方式のステップ2

階層数 `L` と境界通過辺数 `T` を固定し、周期スパン `s(u,v)=y(v)-y(u)+L*t(u,v)` を整える。
固定するのは**境界通過辺の総数**であり、各辺のフラグをすべて固定する方式ではない。

| 手法 | 目的・処理 | 着目点・制限 |
| --- | --- | --- |
| `diff` | 重み付きスパン和の最小化 | 総スパンを抑える基準 |
| `diff_square` | 重み付きスパン二乗和の最小化 | 長辺を強く罰する。現行の既定値 |
| `qp` | 階層変数を連続緩和して求解し、整数へ丸める | 高速化候補。ただし丸め後の制約違反に既知例がある |
| `barycenter` | `diff` の初期解から重心反復・補正 | 初期求解を含むため、反復部分だけの時間で比較しない |

参照：[旧二段階モデル](../src/old_torus_layout/layer_assignment/torus_two_stage.py)、[現行の選択処理](../src/torus_layout/layering/router.py)、[各手法](../src/torus_layout/layering/balance/)。

ここでいう「バランス」は主として辺スパンに関するもの。**層人数の分散や、統計的なスパンの分散を直接最小化している、と表現すると不正確になる。**
二乗和・総和・最大スパン・人数の偏りは、別々の指標として評価する必要がある。

## 3. 交差削減で試したこと

| 試した方式 | 狙い・変更点 | 現在の位置づけ |
| --- | --- | --- |
| 交差最小化ILP | 層内順序、推移律、辺の巻き数を変数化 | 旧系統の数理モデル。巻き数は−1〜1に制限され、巻き数への罰則もあるため、無制限問題の純粋な交差最小化と区別する。[実装](../src/old_torus_layout/crossing_reduction/minimize_crossings_ilp.py) |
| 重心法と循環シフト | 隣接関係から順序を反復改善 | 旧ヒューリスティック。[実装](../src/old_torus_layout/crossing_reduction/minimize_crossings_heuristic.py) |
| 円形重心による初期順序 | 循環構造を踏まえた初期配置を作る | 現行siftingの前段。[実装](../src/torus_layout/crossing/initialization.py) |
| radial sifting | 頂点を順に動かし、局所交差を改善。巻き数も扱う | 現行交差削減の中心。[実装](../src/torus_layout/crossing/sifting.py) |
| global guard | 局所処理中の全体交差数を評価し、最良状態を保持 | 局所改善が他の層間の悪化を招くことに対応。大域最適解を保証する仕組みではない |
| 掃引順序の変更 | 往復、全体循環、現行循環の3方式を比較 | 反復の順序への依存性を調べる実験。[スクリプト](../experiments/evaluate_torus_sweep_direction.py) |

さらに、順序だけを変える条件、巻き数も変える条件、回転を加える条件、guardを加える条件を比較するアブレーションがある。
参照：[構成比較](../experiments/evaluate_torus_framework_ablation.py)、[交差削減比較](../experiments/evaluate_crossing_reduction.py)。

整理上の要点は、**「順序」「巻き数」「探索順序」「全体の最良状態の保持」は、それぞれ別の工夫**ということ。
どの工夫が効いたかは、同一初期状態に対する比較で切り分ける。

## 4. 回り込み・表示境界について試したこと

| 処理 | 狙い | 区別しておきたいこと |
| --- | --- | --- |
| sifting後の回転調整 | 巻き数や配置を調整して回り込みを改善 | 現行APIでは交差が増えた場合に回転前へ戻す。[呼び出し元](../src/torus_layout/crossing/api.py) |
| 各層の切れ目選択DP | 循環順序と交差関係を保ち、表示境界を通過する線分数を最小化 | 与えられた循環埋め込みに対する厳密最適化。階層割当から全てを同時最適化するものではない。[実装](../src/torus_layout/crossing/seam.py) |

階層割当で扱う境界は現行描画の左右、切れ目DPが扱う層内循環方向の境界は上下。
また、「巻き数が非ゼロの辺数」「境界通過線分数」「境界を通る元辺数」「通過回数」は同じ指標ではない。

[境界最適化の既存検証記録](torus_seam_optimization.md)では、全探索と60ケースで最適値が一致したと報告されている。
生成グラフ9ケースでは8ケースで通過線分数が改善し、交差数は全件維持。QP座標の6ケースは通過線分合計21→11、BK座標の3ケースは42→25。
これは特定の生成条件・ローカルライセンスでの既存記録であり、今回の整理で再実験した数値ではない。

## 5. 座標割当・描画で試したこと

| 方式 | 狙い | 現在の位置づけ |
| --- | --- | --- |
| 等間隔配置 | 順序だけで描いた場合の基準 | 座標割当アブレーションの比較条件 |
| BK系の4方向整列・圧縮・中央値統合 | 辺を整列させ、位置を詰める | 現行既定値。[実装](../src/torus_layout/coordinates/brandes_koepf.py) |
| 周期的な射影・平滑化 | 境界をまたぐ関係と層内間隔に対応 | BK系座標の後処理。[実装](../src/torus_layout/coordinates/periodic.py) |
| トーラスQP | 固定順序・巻き数・周期の下で、周期方向変位の二乗和を最小化 | 明示的に選択可能。曲がりへの罰則も比較 |
| トーラスLP | 同じ条件で絶対変位和を最小化 | 明示的に選択可能。QPとは目的が異なる |

階層割当の `qp` と、座標割当の `torus_qp` は別の処理。
座標QP/LPは [optimization.py](../src/torus_layout/coordinates/optimization.py) に実装されている。

[座標方式の既存比較記録](torus_coordinate_assignment.md)では、固定4層・15グラフについて、従来BK＋平滑化に対する集計比として、QPの二乗変位和0.9508、曲がり罰則付きQPの曲がり二乗和0.8491、LPの絶対変位和0.9562が記録されている。
各方式が自分の目的に対応した指標を改善した結果であり、描画品質全般の優劣を示すものではない。

描画自体についても、ダミー表示、左右・上下の同時境界通過、周辺タイル表示を扱ってきた。
境界付近でノード記号が切れるなど、座標目的の改善だけでは解決しない表示上の課題が残る。

## 8. 今の時点で整理できる到達点と未確定事項

到達点は、階層割当・交差削減・切れ目・座標を別々の最適化問題として扱い、それぞれの手法を比較できるパイプラインができたこと。
特に、二分探索の理論整理、局所交差改善に対するglobal guard、固定埋め込みでの切れ目DP、周期を明示した座標QP/LPは、独立して説明できる工夫になっている。

次に記録を補いたいのは以下。

1. **採用・不採用の理由**：重み付き一括モデル、旧ILP、旧ヒューリスティックから現行構成へ移った際の判断。速度、解の質、実装上の問題を分けて残す。
2. **結果の所在**：過去のCSV・図・実行条件を回収し、文書中の数値と対応させる。確認できない数値を一般的な性能として使わない。
3. **現行既定値の根拠**：`diff_square`、掃引順序、5反復、BK＋平滑化が、どの入力群でどの比較に基づき選ばれたか。
4. **完成描画への効果**：スパン二乗和・工程内交差・境界通過の改善が、最終的な辺長・曲がり・可読性へどう影響するか。
5. **残る制約**：階層QPの丸め、探索の非最適終了、大規模時の負担、描画境界付近の表示。

今後の評価案は [実験計画](experiment_plan.md) にある。ただし同文書のE5には「未実装」とある一方、現行コードでは切れ目DPが実装・統合済みである。
計画、旧Memory Bank、現行実装には時点の違いがあるため、この整理では現行コードを基準とした。
