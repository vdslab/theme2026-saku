# Algorithm 2で共通の回り込みを除去できるか

確認日：2026-11-10。

## 結論

指摘された23・8・5から出る辺のケースは、二層だけならAlgorithm 2で解消できる。
しかし、現行のトーラス全体に対して、層回転と切れ目変更だけで上下の回り込みを全て除くことはできない。
回転が未実行だったり、交差増加のguardで差し戻されたりしたためではない。

## 再現対象

- cyclic、25頂点、閉路数2、追加辺確率0.005、seed `3409470963`。
- 階層割当 `diff_square`、13層、sifting 5回、切れ目DPあり。
- 指摘画像の確認時に記録した階層結果を固定して再現。最新の `output/torus_layout/result.json` は後続の実行で別seedに更新されているため使用しない。
- 生成器でseedから元の29辺を再生成し、記録した入力辺と一致することを確認した。
- 同じ階層割当からダミーを再挿入し、初期順序・sifting・Algorithm 2・guard・DPを再実行すると、記録した最終順序と巻き数に完全一致した。最適化ソルバーの再実行は不要。

図で回り込んでいる元辺は `23→12`、`8→9`、`5→24`。
それぞれの細分化後の線分 `(26,12)`、`(8,9)`、`(29,30)` が、同じ層間0→1で巻き数+1を持つ。

## なぜ一層ずつ回転しても消せないか

層回転と切れ目変更は、各頂点が境界をまたいだ回数を `q(v)` とすると、辺の巻き数を
`ψ'(u,v)=ψ(u,v)+q(u)-q(v)` の形で更新する。
閉路に沿って足すと頂点ごとの増減が相殺されるため、**閉路の巻き数合計は変わらない**。

この入力の三つの閉路 `0→…→11→0`、`12→…→23→12`、`5→24→5` は、
細分化した経路上でそれぞれ巻き数合計1を持つ。
Algorithm 2を何回適用しても、この合計を全て0にはできない。
記録した各回転とDPについても、合計 `[1,1,1]` が維持されることを確認した。

当該辺束の巻き数を同時に−1する操作では、これらの合計が `[0,0,0]` に変わる。
これは表示の切れ目を変えるだけではなく、辺の巻き方自体を変える操作である。
今回のケースでは交差を保って実行できるが、一般の入力に適用する際は全体交差の再検査が必要。

## 論文との関係

[Bachmaier 2007のAlgorithm 2](https://www.infosun.fim.uni-passau.de/~chris/down/RadialVisualization.pdf#page=8)
は二層のsifting後に自由層を回転する処理であり、トーラスの循環する全階層から共通の巻きを消す保証ではない。
通常の放射型階層には最内層・最外層があり、最後の階層から最初の階層への接続がない。
トーラスではその接続があるため、余分な巻きが次の層間を経由して戻ってくる。

Algorithm 3のUNWINDは、二層間の全辺から共通の整数巻きを差し引く点で近いが、
論文では長辺の内部線分の競合除去を目的とする。今回の辺束へ適用するにはトーラス向けの扱いを決める必要がある。

上記はUNWIND導入前の確認記録である。
現在はAlgo2の交差チェック後・切れ目DP前に `crossing.unwind.unwind_levels` を追加した。
既定で有効、`--no-unwind` で無効化できる。内部線分がある層間では、その最小巻き数を使う。
内部線分がない層間は省略する。
この例を `src/torus_layout/tests/test_unwind.py` の回帰ケースとして保存し、交差0・境界通過0を検証している。
旧処理の再検証では `reduce_crossings(..., unwind=False)` を指定する。
