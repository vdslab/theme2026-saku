# トーラス階層グラフ描画の実験計画

2026-11-19 更新。対象は現行の `src/torus_layout`。実験は未実施。

## 1. 何を検証するか

主仮説は、有向閉路を含むグラフで、元の辺を階層進行方向に保ちながら、見かけの交差と境界での追跡負担を抑えられる、というもの。条件を三つに分ける。

1. **完成描画の品質**。同じ入力に対し、平面杉山法と放射型杉山法、それに Graphviz `dot` と比較する。有向閉路を持つケースで、逆向き辺・幾何交差・辺の重なり・境界通過・計算時間を併記する。DAG は、周期を導入する利点が少ない入力に対する対照群とする。
2. **各処理の寄与**。直前の入力を固定し、処理の有無や代替法を比較する。局所目的が改善したときは同じ後段に通し、完成描画での交差や辺形状も確認する。厳密な最小値を計算できる小規模入力では、最適性とヒューリスティックの差を検証する。
3. **人が辺を追えるか**。交差や境界通過を代理指標とし、参加者実験で有向辺の向きと最短有向経路を読めるか測る。返答の正誤と時間を測り、周辺タイルの効果を同じ配置上で検証する。

全体比較で交差が減っても、重なりや境界通過が増える場合は、その大きさと発生する入力条件を示す。工程別では、目的値、時間、実行可能性を併記する。主比較と解釈は下表で固定し、その他の指標や条件は感度分析とする。論文ごとの実験目的・比較条件・結果、およびこの設計への反映は文献調査にまとめた。[一次資料の再確認](sugiyama_experiment_literature_review.md#今回の計画に使った一次資料)

## 2. 入力と反復

| 集合 | 設計 | 用途 |
| --- | --- | --- |
| 統制生成 | 4 族 × 50・100・200 頂点 × 辺数 2n・4n × 20 seed = **480 件** | 完成描画と各工程。DAG、弱連結の一般有向グラフ、10 SCC を前向きに連結したグラフ、円環方向の Watts–Strogatz を使う |
| 公開 GraphML | AT&T 有向、Rome 無向、DAGmar の各集合で、10–25・26–50・51–75・76–100 頂点から各最大 50 件。**合計最大 600 件** | 既存ベンチマークとの接続。Rome はファイルごとの固定 seed で各辺を有向化する |
| 小規模の厳密比較 | 階層数は 3 族 × 8・12・20 頂点 × 10 seed = **90 件**。交差と切れ目は 3 階層 × 各階層 2・3 頂点 × 追加辺確率 0.25・0.65 × 10 seed = **40 件** | 階層数探索、巻き数固定の層内順序探索、切れ目選択の照合 |
| 規模比較 | 4 族 × 50・100・200・500・1000 頂点 × 2n・4n × 10 seed = **400 件** | 規模と密度の影響。最初の 3 サイズには統制生成の同じ seed を再利用 |
| 描画確認 | 7 通りの境界分割、4 通りの交差判定の既知例、10 頂点の各生成族 1 件 | 境界・矢印・画像出力を個別に確認 |
| 読み取り課題 | 20・40 頂点 × 2 課題 × 目標経路の境界通過有無 × 3 問 = **24 問** | 本比較と異なる生成 seed。各問に 3 種の表示を作る |

統制生成は全て弱連結で、単位重み・最小スパン 1 とする。DAG と一般有向グラフの連結性は生成時に木で確保する。SCC 連結型はブロック内に閉路を置き、追加辺を同じブロック内または前向きに限定する。Watts–Strogatz は近傍数 4・8、再配線率 0.1。生成後に頂点 ID と入力辺順をシャッフルする。同じ元グラフを全条件に渡し、ケース ID、元の辺列、SCC 統計・次数・相互辺数を保存する。20 seed は各条件のばらつきを把握する初期設計の件数。結果は実際の閉路有無と最大 SCC の構成も確認して解釈する。

公開データは入力ディレクトリを明示する。自己ループ、平行辺、非連結、想定した向きと異なる入力を除外する。AT&T の有向集合は実測で DAG と閉路ありに分ける。DAGmar は DAG のみを採る。Rome の方向は派生データの属性として記録する。各サイズ群の適格件数が 50 未満なら全件を採用し、元ファイルの SHA-256 と選定理由を保存する。[Graph Drawing 公式のデータセット案内](https://www.graphdrawing.org/data.html)

## 3. 工程別の実験

| 対象 | 固定する入力と比較条件 | 見る指標と判断 |
| --- | --- | --- |
| 階層数探索 | 各サイズで一般有向5件、SCC連結5件、Watts–Strogatz 10件。DAG系列は対象外。同じ元グラフで現行の二分探索、固定階層数 `ceil(sqrt(2n))`、小規模で全 `L=1…n` | 全候補の `(左右境界通過辺数, 階層数)` の辞書式最小値との一致、候補ごとの終了状態、求解回数、時間。固定階層数との比較では達成した通過辺数も必ず見る |
| 階層バランス | 同一の `(L, T)` でトーラス辺数最小化時の実行可能解、`diff`、`diff_square`、`qp`、`barycenter` | スパンの和・二乗和・最大値、層サイズ、ダミー数、時間。制約違反を集計してから、妥当な解に共通の後段を適用する |
| 階層割当全体 | 既定探索＋既定バランス、固定階層数＋既定バランス、同じ `T` を固定した `min(n, 2L)` ＋既定バランス | 探索・バランスの合計時間と完了率、実使用階層数、後段の幾何交差・辺長・占有面積。少ない層数と少ない交差が両立する範囲を調べる |
| ダミー挿入 | 同じ階層割当から、旧実装の層内検索、現行の頂点→層対応表、空レイヤーを明示した現行入力 | 同じ層集合での全出力一致、処理時間。辺ごとの連鎖・端点・単位スパンと、階層割当の `Σ(s−1)` とのダミー数の一致を確認する |
| 円形重心初期化 | 同じ分割グラフの入力順と円形重心順。各順から同じ sifting を適用 | 初期交差、sifting 後の交差、時間。初期化だけで減った交差と最終的に残った差を測る |
| sifting・global guard | 同じ円形重心順から、無処理、guard なし、巻き数固定、既定 guard 付き、1・5・10 ラウンド | 層間の交差、ダミー間線分同士の交差、時間。小規模では巻き数を全て 0 に固定し、層内順序を列挙して得た独立の反転数と比較 |
| Algo2 回転 | sifting 直後を固定し、無処理、平均角度差による回転、回転＋交差増加時の復元 | リフト上の角度変位（1 周を 1 とする）の総和・最大値、巻き数、交差。巻き数の本数だけでは線分の長さを判定しない |
| UNWIND-LEVEL | guard 付き回転の直後を固定し、無処理、ダミー間線分がある層間のみ補正、ダミー間線分がない層間の補正も有効 | 上下境界通過線分数、巻き数の絶対値の和、交差数。交差保存を確かめ、共通巻き除去が有効なケースを数える |
| 切れ目 DP | 回転直後を固定し、無処理、各層を一つずつ動かす貪欲法、現行 DP。別実験で UNWIND を DP 前にだけ適用する条件と DP 後の候補も比較する条件 | 上下境界通過線分の差、交差数、時間。小規模では固定した循環順序の全切れ目を列挙し、DP の目的値が一致するか確認 |
| 交差削減全体 | ダミー挿入結果を固定し、現行 API で UNWIND と DP の有無の 2×2 条件 | 工程時間、交差・巻き数、共通 BK 後の幾何交差・境界通過の元辺数・辺長。両処理を単独で加えた効果と相互作用を読む |
| BK の競合マーク・整列・圧縮、方向統合、射影 | 同一の層・順・巻き数。既定 BK から競合マークのみ無効、ブロック整列のみ無効、ブロック圧縮を等間隔化で置換。別に、単一走査方向と中央値統合、および射影前後を比較。平滑化は 0 回 | 内部線分の整列・曲がり・長さ、制約サイクルによる失敗、射影による描画領域・層内順序・周期的な頂点間隔の違反解消 |
| 周期平滑化と座標割当全体 | 同一の埋め込みに、等間隔、等間隔＋平滑化、BK＋射影（平滑化 0・4・10 回）、QP、LP、曲がりペナルティ付き LP、3×3 BK | 直線化した内部線分数、元辺の曲がり・長さ、違反、交差、時間。3×3 BK は周期を再設定するため、周期・基本領域面積・コピー外へ落ちた線分数も示す |
| 周期境界の線分分割 | 手計算可能な入力で、非周期、左右のみ、上下の正負、角、両方向かつ複数周を検査 | 出力線分数、分割長の和、入口と出口の周期的な接続、始点・終点、終端のみの矢印。既知の交点・共有端点・重なりでも交差測定器を検査 |
| 描画全体・周辺タイル | 同一座標を使い、現行の描画 API で周辺表示なし／ありの PNG を保存 | Figure 構築時間、保存・合成時間、画素数・ファイルサイズ。読み取りの効果は次節の参加者実験で測る |

左右境界は **階層方向**、上下境界は **層内循環方向**。階層数探索が変えるのは前者で、切れ目 DP が最小化するのは後者。階層数の全候補比較は Gurobi が最適または実行不可能と確定した候補を根拠にする。「厳密照合」の範囲は各定式化の許容領域に限る。特に sifting の列挙は**巻き数固定**、切れ目 DP の列挙は**固定した循環順序と基準の巻き数から得られる切れ目**を対象とする。二分探索の理論条件は既存の証明に従う。[階層数探索の正当性](layer_count_search_correctness.md)

## 4. 全体比較と解析

- **主比較**。既定の `run_pipeline`、リポジトリの平面杉山法（Eades–Lin–Smyth の閉路除去、最長経路階層割当、中央値法＋隣接交換、BK 系配置）、放射型（閉路除去、終点を外周に揃える階層割当、円形順序・放射曲線）、`dot` の左から右への描画。既定トーラス対平面杉山法を主比較とし、放射型と `dot` で傾向の依存性も確認する。UNWIND・DP の両方を無効にした条件で境界処理の寄与を測る。補助の円筒条件は、同じトーラス階層割当を使い、層内循環方向の巻き数を 0 に固定して sifting し、回転・UNWIND・DP を省く。階層方向だけの周期でも同程度の交差削減が得られるかを見る。
- **幾何交差**。異なる元辺の中心線が横切った位置を各辺対で数え、交差した辺対数も記録する。同一の共有端点を除き、接触と線分の重なりは別集計。トーラスの境界上は一つの基本領域に帰属させる。放射曲線は既存描画と同じサンプリング、`dot` の折れ線モードでは Graphviz の制御点を曲線区間ごとに 16 分割して近似する。線の太さとノード領域は測定対象外。
- **その他の品質**。左右・上下別に、切れる元辺数、分割後線分数、通過回数を数える。負の階層進行は元辺で比較する。平面法と放射法で相互辺が閉路除去後に同一経路になるときは元の矢印方向を戻し、重なりを記録する。辺長はネイティブ座標と表示枠の対角長で割った値を保存する。ネイティブ面積は方式ごとの単位で解釈する。折れ点は 1 度超の方向変化で数え、放射曲線の曲がり数は欠測とする。
- **規模比較**。現行パイプラインの階層数探索・バランス・ダミー挿入・交差削減・座標割当の壁時計時間を測る。描画や評価器はタイマから外す。元のノード・辺数と、ダミー挿入後のノード・線分数で集計し、完走率、全体時間の中央値・90 パーセンタイル、完走プロセスのピーク RSS を併記する。RSS にはインタープリタとライブラリの常駐領域を含む。
- **統計**。計算比較の単位は元グラフ。条件差は同じグラフ上で引き、平均差・中央値・減少／同値／増加件数、グラフ単位の bootstrap 95% 区間を出す。差が 0 のケースを残す。DAG・単一 SCC・複数 SCC と生成族／規模を表示し、総集計は補足とする。区間は個別比較の記述に使う。条件の確定には実験前に指定した主指標を優先し、一部の好結果から広い優越を導かない。
- **実行失敗**。既定で 1 ソルバーモデル 15 秒、`dot` 60 秒、worker 600 秒。全体比較はグラフと方式の組ごとに独立の worker を使い、工程別は共通の前段を再利用するためグラフごとに働かせる。Gurobi 1 スレッドで、最適終了、時間制限、実行不可能、解の有無、下界が取得できた場合は下界を保存する。制約違反のある解は後段の品質から外す。時間制限付きの実行可能解を含む対応ペア数を記録し、確定解だけの再集計にも生データを使う。未着手の条件はグラフ単位の進捗と照合する。品質ペア数と全試行の完了率の両方を示す。
- **論文用の図**。完成図の交差・境界通過の対応散布図、階層数ごとの最小通過辺数、sifting の回数と交差・時間の曲線、BK と LP/QP の辺長・曲がり分布、規模と工程別時間の図を作る。代表画像には中央的なケースと悪化例を用い、選定規則を先に定める。

平面と放射はリポジトリ内の実装を使用する。放射型の論文は比較設計の根拠であり、実装との機能差は結果の解釈に含める。Graphviz は外部の実用基準として `--dot` で有効化し、バージョンを記録する。[Graphviz の dot](https://graphviz.org/docs/layouts/dot/)

## 5. 読み取りの参加者実験

同じ画面サイズ・描画スタイルによる **平面杉山、トーラス中央のみ、トーラス＋周辺タイル**の 3 条件。トーラス 2 条件の中心領域のサイズと配置を一致させる。各参加者は 24 問を解き、同じグラフは 1 回だけ見る。3 種の出題フォームに均等に無作為割付すると、各項目が全体で 3 条件に回る。先に練習課題で矢印と境界の読み方を説明する。本番前に画像の拡大率、時間の記録方法、欠測の扱いを固定する。

- 課題は「A と B を結ぶ辺の向き」と「A から B までの最短有向経路の辺数」。後者は最短路が一意で、長さ 2–5 のケースを使う。境界通過の有無はトーラス配置上の該当辺・該当経路で定め、全表示条件で同じ質問を採点する。
- 主比較は**境界をまたぐ最短経路の正答率に対する周辺タイルの効果**。補助比較は平面との正答率差、辺の向き課題、正答時の所要時間。速さは正答率と併記する。課題、境界有無、グラフ規模のバランスを固定し、同じ項目集合に対する参加者単位の対応差と区間を示す。
- 予備調査で設問の難易度、画面上の矢印の判別性、制限時間を確認し、実用上検出したい正答率差から参加者数を決める。本実装は刺激・フォーム生成と回答の採点・集計を提供する。募集、同意、説明、実際の提示と計時は実験担当者が行う。

## 6. 実行方法

リポジトリルートから、出力先に未作成のディレクトリを指定する。以下は実行例。通常はルートの `.env` の Gurobi 設定を利用する。ローカルライセンスを選ぶ場合は `--local-license` を明示する。

```sh
./theme2026-saku/bin/python experiments/run_torus_study.py oracles \
  --profile main --output experiments/results/torus_oracles

./theme2026-saku/bin/python experiments/run_torus_study.py framework \
  --profile main --dot dot --benchmark att=path/to/att_graphml \
  --benchmark rome=path/to/rome_graphml --benchmark dagmar=path/to/dagmar_graphml \
  --output experiments/results/torus_framework

./theme2026-saku/bin/python experiments/run_torus_study.py crossing \
  --profile main --output experiments/results/torus_crossing
```

`run_torus_study.py` のグループは `framework`、`layering`、`subdivision`、`crossing`、`coordinates`、`drawing`、`oracles`、`scaling`。他の工程もグループ名と出力先を置き換えて実行する。少数確認には `--profile quick` と `--limit` を使える。`--dot` と `--benchmark` は利用可能な範囲で追加する。外部データはあらかじめ展開した GraphML のディレクトリを指定する。

| 出力 | 内容 |
| --- | --- |
| `settings.json`・`inputs.jsonl`・`benchmark_audit.csv` | 設定・版・入力グラフ・公開ファイルの選定記録 |
| `results.csv`・`rows.jsonl` | 手法・グラフごとの品質、時間、状態。JSONL には個別のソルバーモデルの記録を含む |
| `cases.csv`・`case_progress.jsonl` | 各 worker の終了状態と記録した条件数 |
| `summary.csv`・`paired.csv` | 層別の記述統計、対応差と比較対象。失敗は状態の件数で確認できる |
| `images/` | `drawing` グループの描画確認画像 |

```sh
PYTHONHASHSEED=0 ./theme2026-saku/bin/python experiments/prepare_torus_readability.py prepare \
  --output experiments/results/readability_stimuli

./theme2026-saku/bin/python experiments/prepare_torus_readability.py score \
  --stimuli experiments/results/readability_stimuli \
  --responses path/to/responses.csv \
  --output experiments/results/readability_summary.csv
```

刺激生成は画像、`form_0.csv` から `form_2.csv`、`answer_key.csv`、候補入力の採否一覧を出力する。回答 CSV の列は `participant,group,trial,answer,seconds`。参加者 ID は匿名化し、同じフォームの `trial` を使う。`score` は完全回答の参加者を主集計に使い、正答時の時間比較については各条件に正答がある組数も記録する。

2026-11-20 の計算実験では、実行可能な範囲に生成条件を絞って計測した。`--sizes`、`--densities`、`--seed-count` で生成条件を指定し、`--benchmark-only` で公開データのみを評価できる。`--jobs` で独立ケースを並行処理でき、指定した並行数は所要時間の解釈に含める。今回の実際の条件・評価・追加実験は [HTML報告書](../output/torus_experiment_20261120/index.html) にまとまっている。
